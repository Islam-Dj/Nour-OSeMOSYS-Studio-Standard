# Working on Nour OSeMOSYS Studio

A short guide for anyone who wants to change the Studio: how it is built, where things are, how to test.

## How it is built

- **No framework, no build step.** The page is plain HTML, CSS and JavaScript (`web/`), loaded by `web/index.html` in
  a fixed order. Every file adds functions to the page; there are no modules or imports. A function defined in an
  earlier file can be used by any later one.
- **Pages are drawn as HTML text.** Each page of the side panel builds its HTML in one template string
  (`drawer.innerHTML = ...`), then wires its buttons. After an edit the page is simply drawn again.
  `keepplace.js` then puts back what the user had open, typed, scrolled and focused, so a page needs no special code
  for that. A page that scrolls to a target itself (go to a cell) calls `KEEP.jump()`.
- **The server is small.** `server/` (Python, standard library only) serves the page and keeps cases, runs and model
  files on disk. `engine/` holds the solvers' side: HiGHS, GLPK, CBC and Gurobi runs, Monte Carlo, robust decisions,
  MUIO import and export.
- **The single-file page** `Nour_OSeMOSYS_Studio.html` is generated by `tools/build_portable.py` from `web/`: never edit
  it by hand.

## Where things are (web/js)

| File | What it does |
|---|---|
| `core.js` | start-up texts: the built-in model files and the examples |
| `i18n.js`, `i18n_fr.js`, `i18n_es.js`, `i18n_ar.js` | the language of the Studio: the translator and the French / Spanish / Arabic tables (generated) |
| `keepplace.js` | keep the user's place when a page is drawn again |
| `theme.js` (and `css/theme.css`) | the colour of the Studio and the design rules: edges, corners, selection, fonts |
| `gmpl.js`, `model.js`, `schema.js` | read a data file and a model file; the model index; the data writer |
| `editing.js`, `grids.js`, `entities.js` | editing: values, the parameter grids, the page of one technology / commodity / storage... |
| `setup.js` | the Model setup pages |
| `diagram.js`, `diagview.js`, `diagram_export.js`, `icons.js`, `browser.js` | the diagram of the system and the model browser |
| `checks.js` | the data checks (run in small slices when the Studio is idle) |
| `units.js`, `systems.js`, `topics.js`, `descriptions.js` | units (proposed by system), systems, colours, descriptions |
| `library.js`, `models.js` | cases (grouped by model), model files, the start dialog |
| `run.js`, `monitor.js` | solving and the jobs bar |
| `results.js`, `resultdesc.js`, `chartstyle.js` | results tables and charts |
| `ask.js` | Ask the results: questions in four languages read from the model's own names (no AI), answers from the results |
| `montecarlo.js`, `rdm.js`, `rdm_more.js` | Monte Carlo, robust decision making (its extra charts, Excel and package in `rdm_more.js`) |
| `scenarios.js`, `onoff.js`, `vintage.js`, `batch.js`, `merge.js` | scenarios, years on/off, vintages, editing many items, merging models |
| `muio.js`, `xlsx.js`, `describe.js` | MUIO export, Excel files, the model description |
| `info.js`, `windows.js`, `msel.js`, `util.js`, `main.js` | the Info menu, second windows, the searchable lists, helpers, start-up |

`engine/muio_api/` is MUIO's own code (Apache-2.0), kept exactly as MUIO ships it: do not reformat or change it.

## Run and test

```
pip install -r desktop/requirements_app.txt
python run_studio.py                      # http://127.0.0.1:8775
python tests/run_tests.py                 # every check (server, solvers, cases, and the page in a real browser)
```

The browser tests are `tests/*_test.js` (Playwright). Each prints `ok` / `FAIL` lines; `run_tests.py` runs them all.
Add a test for each change you make, next to the others, and register it in `run_tests.py`.

## Documents

The User Guide and the Parameter Reference (`docs/`, shown in the Studio from `web/data/docs/`) are written in LaTeX,
outside this repository. After compiling them, `python tools/sync_docs.py <folder of the compiled documents>` copies
both PDFs to `docs/` and `web/data/docs/`, and writes the page of every parameter (`web/data/docs/param_pages.json`)
for the Info menu and the **i** buttons (a parameter section keeps its label `\label{sec:<Parameter>}`).

## Code style

- JavaScript: Prettier (`.prettierrc.json`): `npx prettier --write "web/js/*.js" "tests/*.js"`.
- Python: Black (`pyproject.toml`): `python -m black .`.
- Comments say *why*, in plain English.
- Design: `css/theme.css` holds the rules (one colour, 2 px rounded edges, two fonts); use its tokens (`--th`, `--line`, `--th-soft`), not new colours. Colours of data: one light colour family, never a rainbow. Units: each item in the unit of its system.

## Languages

The Studio is written in English. `i18n.js` translates what the page shows from the tables in `tools/i18n/tr/*.tsv`
(English, Spanish, Arabic, separated by tabs) and `tools/i18n/fr/*.tsv` (English, French; `{0}`, `{1}` stand for values kept as they are). After adding rows run
`python tools/i18n/gen_i18n.py` to rebuild `web/js/i18n_fr.js`, `i18n_es.js` and `i18n_ar.js`. Write new texts in plain English as usual;
mark an element `data-notr` if its text must never be translated (a code, a name the user typed). Never test the text of an
element in code (`b.textContent === 'All'`): keep the value in a `data-` attribute. `tools/i18n/find_untranslated.js`
lists the texts a running Studio still shows in English.

## Editions

`web/js/core.js` sets `EDITION` to `'standard'` (`STANDARD` is true): this edition has the standard OSeMOSYS
model built in. Code written for features that other editions have tests `STANDARD` and stays off here.

## Where to start for common changes

- **A new parameter of the model**: it is read from the model file automatically. Add its description in
  `descriptions.js`, its group in `setup.js` if it belongs on a Model setup page, and a check in `checks.js` if wrong
  values are likely.
- **A new page in the side panel**: build its HTML in one function, give it a title line (`<div class="code">...`)
  so `keepplace.js` knows the page, and wire its buttons after `innerHTML`.
- **A new solver option**: `run.js` (the form) and `engine/highs_run.py` or `engine/gurobi_run.py` (the run).
